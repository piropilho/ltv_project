# 서울시 아파트 입지 특성을 반영한 LTV 리스크 평가 모델

단지별 **매매 유동성 예측**을 근거로, 정부가 정한 LTV 상한 이내에서 은행이 담보의 실제
위험도를 반영해 얼마까지 빌려줄 수 있는지 정교화하는 프로젝트. 서울 동대문구를 파일럿으로
검증했습니다.

📑 **발표 자료**: [프로젝트 발표 슬라이드](https://drive.google.com/file/d/1CjBBEDC9PEqisKBxgzbS6idDOQS6YsTn/view?usp=drive_link)

## 왜 이 프로젝트인가

### 1. 문제의식 — 일률적 규제의 사각지대

LTV 규제는 2017년 투기과열지구 강화(40%/60%)를 시작으로 고가주택 구간별 차등(2019),
규제지역 완화(2022), 재강화(2025.9)를 거쳐 2025년 10월 서울 전역으로 규제지역이 확대되며
**LTV 40% 일률 적용**으로 귀결됐습니다. 8년간 강화와 완화를 반복했지만, 결론은 지역·단지의
위험도 차이를 반영하지 않는 단일 기준이었습니다.

그런데 같은 서울시 안에서도 자치구 단위로만 봐도 담보 위험도는 이렇게 다릅니다
(2019~2025, 국토부 실거래가 기준):

- **가격 변동성(MDD)**: 최소 21.4%(송파구) ~ 최대 58.0%(동작구), 평균 31.8%
- **거래 활동성**: 노원구 33,891건 vs 종로구 3,526건 — 약 9.6배 차이

이 위험도 차이가 실제로 문제가 되는 지점은 **담보가 부실화되어 경매로 넘어갈 때**입니다.
법원경매는 유찰될 때마다 최저입찰가를 20%씩 낮추기 때문에(감정가 100% → 1회 유찰 80% →
2회 64% → 3회 51.2%), "안 팔리는 담보"일수록 은행이 회수하는 금액이 가파르게 줄어듭니다.
실제로 국내 담보대출의 평균 손실률(LGD)은 5.9%이고, 이 손실률을 결정하는 최대 요인이
"경매낙찰률" — 담보가 얼마나 잘 팔리는가입니다.

**결론**: 은행 입장에서 담보가 경매로 넘어갔을 때 발생하는 손실은 결코 작지 않은데, 현재
규제는 이 위험도 차이를 전혀 반영하지 않습니다.

### 2. 접근 방법 — 두 축으로 리스크를 검증

담보 리스크를 "가격이 얼마나 흔들리는가(변동성)"와 "얼마나 쉽게 팔리는가(유동성)" 두
관점에서 각각 검증했습니다.

| | Track A: GWR (변동성) | Track B: XGBoost (유동성) |
|---|---|---|
| 질문 | 오늘 이 단지가 왜 위험한가 | 향후 1년, 이 단지가 얼마나 자주 거래될까 |
| 타겟 | MDD(최대낙폭)/CV(변동계수) | 향후 1년 거래활동비율 |
| 검증 | 전체표본 적합 (Adjusted R², AICc) | walk-forward (시간순 검증, 랜덤분할 금지) |
| 결과 | 입지특성 추가해도 조정R² 0.39→0.43, 유의미한 개선 아님 | R² = 0.687 |
| 채택 여부 | 참고자료로만 활용 | **최종 LTV 산출의 핵심 근거** |

가격 변동성만으로는 담보 리스크를 설명하는 데 한계가 뚜렷했고, 반면 입지특성은 매매
유동성을 잘 설명했습니다 — 그래서 최종적으로 리스크를 **유동성** 관점으로 재정의했습니다.

예측된 유동성은 다음 로직으로 LTV에 반영합니다: 단지의 유동성 백분위(0~100)를 구해서,
정부 LTV 상한(예: 40%)과 하한(예: 30%) 사이에 **연속적으로 선형 매핑**합니다. 등급이 아닌
연속값을 쓴 이유는 2021년 한국이 신용등급제에서 신용점수제로 전환한 사례와 같은 논리입니다
— 등급 경계에서 생기는 불연속·불공정을 방지하기 위함입니다. (상/하한값은 예시 파라미터로,
실제 적용 시 정책 설계자·은행의 판단에 따라 조정 가능합니다.)

### 3. 핵심 결과

유동성 예측 모델을 "최근 추세가 그대로 이어질 것"이라는 나이브 베이스라인과 비교했을 때:

- **MAE 13.8%, RMSE 25.1% 개선**
- **백분위 순위상관 0.797** (나이브 0.684) — 실제 LTV 로직이 순위(백분위) 기반이므로 이
  지표가 가장 직접적인 성능 지표
- 평균 백분위 오차 13.85%p → **LTV 환산 시 평균 오차 약 1.4%p** 수준

### 4. 기대효과 — 은행의 LGD 절감

LTV가 낮아지면 담보 커버리지가 두꺼워져 손실률(LGD)이 구조적으로 낮아진다는 건 신용리스크의
표준 원리입니다. 가장 위험한 담보군(유동성 하위 25%)을 기준으로 계산하면:

- 현행 일률 적용(40%) 대출액 대비, 모델 적용 시 대출액이 약 21.8% 감소
- 국내 평균 LGD(5.9%) 기준, 건당 기대손실이 **1,254만원 → 980만원 (-274만원, -21.8%)**
  으로 감소 (LGD율 자체의 추가 하락은 반영하지 않은 보수적 추정치)

### 5. 이 프로젝트의 성격

새로운 대출 서비스나 은행 상품을 제안하는 것이 아니라, **"일률적 LTV 규제가 놓치고 있는
부분은 무엇인가"에 대한 실증적 분석**입니다. 정부·은행이 참고할 수 있는 데이터 기반
근거자료를 만드는 것이 목표이며, 나이브 베이스라인 대비 유의미한 성능 개선을 실제로
확인했다는 점에서 제안할 만한 근거가 있다고 판단했습니다.

## 왜 유동성을 리스크 지표로 쓰는가 (LGD 관점, 상세)

"리스크"라고 하면 보통 가격이 얼마나 떨어지는지(변동성)부터 떠올리기 쉽지만, 은행
입장에서 실제로 손실이 확정되는 시점은 **대출자가 상환하지 못해 담보를 경매에 넘길
때**입니다. 이때 손실 규모(LGD, Loss Given Default)를 결정하는 건 "가격이 얼마나
떨어졌는가"만이 아니라 **"그 담보가 얼마나 쉽게, 제값에 팔리는가"(유동성)** 입니다.
거래가 드문(비유동) 단지는 경매에서 매수자를 찾기 어려워 낙찰가가 시세 대비 크게
할인되는데, 이건 가격 자체가 안 떨어졌어도 발생하는 손실입니다.

- **실증 근거**: 2019→2024년 노원·도봉·강북(노도강) 지역 아파트 경매 건수가 약 4배
  증가(170→657건)했고, 같은 기간 매각가율(낙찰가/감정가)은 92.7 ~ 103.7%에서
  78.2 ~ 89.5%로 떨어졌습니다 — 거래가 얼어붙는 시기에 매각가율도 함께 무너진다는
  실제 사례입니다.
- **왜 변동성(MDD/CV)이 아니라 유동성인가**: 처음엔 "입지특성이 가격 변동성을 설명할
  것"이라는 가설로 시작했지만, 검증 결과 설명력이 낮았습니다(R² ~ 0.05,
  `근거자료/panel_feature_selection.py`). 반면 같은 입지특성(세대수/역세권/상권 등)은
  **유동성**은 잘 설명했고(R² ~ 0.7 이상, `liquidity_feature_selection.py`), 그 유동성
  예측값 자체가 LGD를 구성하는 핵심 요소이므로 "입지특성 → 유동성 예측 → LGD 리스크
  → LTV 차등"이라는 인과사슬이 성립합니다. 반대로 변동성 지표(MDD)는 비유동 단지일수록
  거래가 드물어 관측 자체가 왜곡되는 문제까지 발견돼(`근거자료/ltv_discount_calibration.py`)
  최종 근거에서 완전히 제외했습니다.

## 핵심 모델 설명

전체 파이프라인은 "유동성을 예측하는 모델"과 "그 예측값을 LTV로 바꾸는 로직" 두
단계로 나뉩니다. 아래는 각 모델을 직접 고치거나 확장하려는 사람을 위한 설명입니다.

### 1. 유동성 예측 모델 — `liquidity_forward_prediction.py`

**질문**: "이 단지를 지금(t 시점) 사면, 향후 1년간 얼마나 자주 거래될까?"

- **관측 단위**: (단지, 분기) 패널. 분기는 3/6/9/12월 기준 28개 분기(2019 ~ 2025).
- **타겟**: `forward_activity_ratio_1y(t)` = t+1 ~ t+4분기 중 거래가 있었던 분기의
  비율 (0 ~ 1). 미래 시점이므로 t까지의 정보만으로 피처를 만들어야 함(누수 방지).
- **채택된 피처 15개** (`BASELINE_FEATURES` 10개 + STEP1/4/6에서 추가 채택된 5개):
  - 베이스라인: `trailing_activity_ratio`(직전 4분기 거래활동비율, 모멘텀), `unit_cnt`
    (세대수), `population_t`/`living_population_t`(t시점 인구), 경사도 통계량 6개
    (`slope_*_300m`)
  - 추가 채택: `commercial_index_lasso19_t`(상권지수), `pop_growth_mom_t`(인구증가율),
    `price_momentum`(t시점 대비 t-4시점 가격 변화율), `days_since_last_tightening_t`/
    `n_tightening_past_1y_t`(정책규제 경과일/최근 1년 규제 횟수)
- **모델**: XGBoost 회귀 (`n_estimators=150, max_depth=3, learning_rate=0.05`, 그 외
  `XGB_PARAMS` 참고 — 표본이 작아(n≈5,100) 트리를 얕고 보수적으로 설정).
- **검증**: walk-forward(시간순 확장윈도우) 4폴드. 랜덤 K-fold는 미래 정보 누수 위험이
  있어 금지. **가중평균 R² = 0.687**.
- **피처 채택/기각 실험 로그**: 파일 상단 docstring에 STEP0 ~ STEP7 전체가 남아있습니다.
  요약하면 "시장 전체 활동수준"이나 "12분기 트레일링 병행"처럼 표본을 깎거나 학습 때
  못 본 시장국면에서 외삽이 필요한 피처는 walk-forward 성능이 떨어져 기각됐고,
  "정책규제 경과일"처럼 값의 범위가 자연스럽게 bounded된 피처는 안정적으로 개선을
  가져왔습니다. 새 피처를 추가할 땐 이 패턴(외삽 문제, dropna로 인한 표본 손실)을
  먼저 의심해보세요.
- **과적합 점검**: `근거자료/liquidity_forward_overfitting_check.py`가 폴드별
  train/test R² 격차를 확인합니다 — 표본이 늘어나는 뒤쪽 폴드일수록 격차가 줄어드는
  걸 확인해(0.196→0.066→0.054→0.016) 과적합이 아니라 초반 표본 부족 문제로 판단.

### 2. LTV 산출 모델 — `ltv_scoring.py`

**질문**: "위 예측값을 가지고, 단지별로 승인 LTV를 몇 %로 제안할까?"

1. `liquidity_forward_prediction.py`와 동일한 피처셋으로 XGBoost를 **전체 이력
   데이터(n≈5,100)로 재학습**합니다 (walk-forward는 검증용이고, 실제 서비스용
   모델은 가진 데이터를 전부 써서 다시 학습하는 게 표준적인 관행).
2. **가장 최근 분기(2025년 12월)** 시점 기준으로 각 단지의 피처 스냅샷을 만들어
   향후 1년 유동성을 예측합니다. 이때 정책규제 경과일 등 시간 피처는 "오늘 진짜
   날짜"가 아니라 데이터의 마지막 관측 분기를 기준으로 계산합니다 — 학습 때 본 적
   없는 범위로 벗어나면 트리모델이 외삽을 못 해 성능이 떨어지는 문제(STEP2에서 확인)를
   피하기 위함입니다.
3. 예측값의 **백분위 순위(0 ~ 100, 동대문구 내 상대순위)** 를 구합니다.
4. 백분위를 **정부 LTV 상한(40%, 2025.10.15 대책 기준 동대문구 투기과열지구+조정대상지역
   무주택 실수요자 상한) ~ 최저 LTV(30%) 구간에 그대로 선형 매핑**합니다:

   ```
   assigned_ltv_pct = LTV_FLOOR + (LTV_CAP - LTV_FLOOR) * percentile / 100
   # 예) 백분위 100% -> 40.0%,  백분위 50% -> 35.0%,  백분위 0% -> 30.0%
   ```

   원래는 4분위 이산 등급(1 ~ 4등급)으로 설계했었는데, "이게 실제 여신심사 관행과
   같냐"는 질문에 확인해보니 아니었습니다 — 한국 개인신용평가는 2021년
   신용점수제 전환 이후 이산 등급이 아니라 0 ~ 1000점 **연속 점수**로 대출조건을
   차등합니다. 그래서 "신용점수제와 같은 원리"라는 설명이 실제로 성립하도록
   연속 선형 매핑으로 바꿨습니다.

   할인 폭(최대 -10%p, `LTV_MAX_DISCOUNT`)은 통계적으로 재도출된 값이 아니라 기획
   단계에서 설정한 예시 파라미터입니다. 이 폭을 단지별 실측 가격변동성(MDD)으로
   직접 재계산해보려는 시도도 했는데(`근거자료/ltv_discount_calibration.py`)
   결과가 반대 방향으로 나와(비유동 단지는 거래가 드물어 MDD가 오히려
   과소추정됨) 기각하고 예시 값을 유지 중입니다. 실제 적용 시에는 정책 설계자·은행의
   판단에 따라 조정이 필요합니다.
5. 결과를 `data/csv/ltv_assignment.csv`로 저장하고, `demo.py`가 이 파일을 그대로
   읽어서 조회용으로 씁니다.

### 3. (참고용) 가격 변동성 모델 — `gwr_analysis.py`

지리적 가중회귀(GWR)로 "왜 지금 이 단지가 위험한가"를 MDD(최대낙폭)/CV(변동계수)
기준으로 설명하는 모델입니다. 실거래 데이터만으로 만든 베이스라인과 입지변수(경사도/
학군/교통)를 추가한 확장모델을 비교했지만 개선폭이 크지 않았고(조정R² 0.39→0.43),
`liquidity_feature_selection.py`/`근거자료/panel_feature_selection.py`로 입지특성이
가격 변동성 자체를 잘 설명하지 못한다는 것(R² ~ 0.05)도 별도로 확인했습니다. 그래서
**최종 LTV 산출에는 쓰지 않고 참고자료로만** 남겨뒀습니다 — "왜 변동성이 아니라
유동성을 리스크 지표로 썼는가"를 설명할 때 근거로 쓰면 됩니다.

## 환경 변수 (`.env`) — 크롤링 스크립트를 새로 돌릴 때만 필요

데모 실행에는 필요 없습니다. `데이터 크롤링/`의 스크립트를 직접 실행해 데이터를
새로 수집하려는 경우에만 `.env.example`을 참고해 아래 키를 채우세요.

```
MOLIT_SERVICE_KEY=공공데이터포털에서 발급받은 디코딩 서비스키
KAKAO_REST_API_KEY=카카오 디벨로퍼스에서 발급받은 REST API 키
```

`MOLIT_SERVICE_KEY`는 국토교통부 실거래가/전월세 API와 한국부동산원 세대수 API에
공통으로 쓰입니다 (data.go.kr 계열은 데이터셋별 개별 승인 후 동일 키 공유).
